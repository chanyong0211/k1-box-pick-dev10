1. 문제와 과제

  • 문제 (p.2): 긴 로코매니퓰레이션에는 메타 기술(나르기·밀기·차기)을 실행하는 것 외에 그것들을 닫힌 루프로 잇고 실패에서 스스로 회복하는 능력이 필요하다.
  • 기존 표현의 딜레마: 조밀한 HOI 궤적(HDMI, OmniRetarget)은 정밀하지만 계획하기 어렵고, 암묵적 기술 임베딩(LessMimic)은 압축적이지만 해석·조합이 어렵다 (p.2, 표 1).
  • 제안: 접촉 흐름(contact flow) = 소수 몸체의 미래 목표 + 손·발 4 개 이진 접촉 신호. 계획(CF-Gen)과 실행(CF-Track)이 이 표현 하나로 연결된다 (p.4).
  • 평가 과제 (p.7, 부록 B): 메타 기술 Carry Box, Push Suitcase(+ Slide Box, Kick Ball, Relocate Ball), 연결 Stack Boxes(상자 3 개 쌓기), Push-Stack Boxes(여행가방 밀고 그 위에 상자).

실행 (시뮬 평가·실기)

(선택) VLM: 물체별 목표 위치·기술 선택→ CF-Gen (규칙, 학습 없음): 단계 템플릿 → 접촉 앵커 → IK 키프레임(최대 20 반복) → 보간→ 미래 11 시점 질의 → 접촉 흐름→ CF-Track (학습 끝, 고정)→ G1

CF-Gen 세부 (p.5–6)

  • 단계 템플릿: 기술마다 손으로 만든 단계 블록(접촉 의미 포함) 순서. 긴 과제는 상위 단계 상태가 물체·기술·목표를 바꿈.
  • 키프레임: 각 단계의 끝 자세를 물체 기하로 정함. 걷기 단계는 발목 목표만, 나머지 관절은 기본 자세. 접촉 단계는 접근 방향과 접촉 앵커를 골라 발목·손목 끝 자세를 정하고 나머지는 제약 IK 로 풂.
  • IK (식 1): 변수 = 골반 높이 zpelvis, 골반 pitch θpitch, 모든 관절 q. 허리 roll·yaw 는 몸통 안정을 위해 제외. 손실 = Σe∈{손목, 발목} ‖FKe − xetar‖² + λ‖q − qdefault‖², 최대 20 반복.
  • 보간: 골반 위치·관절은 선형, 골반 회전은 SLERP, α = t / T.
  • 접촉 흐름 구성: 보간된 조밀 궤적을 미래 오프셋 T = {0, 1, 2, 3, 4, 8, 12, 16, 24, 32, 50} 프레임에서 뽑아 현재 몸통 yaw 기준으로 변환.
  • 재계획: 50 Hz 로 관측 물체 상태와 계획 물체 상태의 거리 δt 를 보고 ε 넘으면(떨어뜨림, 접촉 실패) 즉시 현재 상태에서 다시 계획. ε 값은 논문에 없음.

6. teacher → student / 증류

해당 없음 — 증류 단계가 없다. CF-Track actor 가 물체 6D 자세·바운딩 박스를 직접 받고(실기는 MoCap), critic 만 몸통 오차·선속도를 더 본다. 코드 rsl_rl 포크에 distillation.py·student_teacher.py 가 있지만 등록된 과제는 PPO·AMP 뿐이다.

11. 우리에게 가져올 것

  1. 가져올 것 — 단계 구조와 명목 자세를 IK 로: Carry Box 의 접근 → 쪼그려 잡기 → 들기 → (운반) → 서기를 우리 1 단계(집기·서기·유지)에 그대로 대응시키고, 각 단계 끝 자세를 상자 기하에서 IK 로 구한다. IK 변수를 골반 높이·골반 pitch·팔 관절로 두고 허리 roll·yaw 는 빼는 것은 우리 행동 공간(골반 높이 0.335–0.77 m, pitch ±45° + 상체 11)과 거의 같다. 이 IK 해를 상위 정책의 "명목 명령"으로 두고 정책은 그 위 델타만 내면 탐색 공간이 줄어든다.
  2. 근거 — 허리 회전은 빼라: OmniContact 는 몸통 안정을 위해 IK 에서 허리 roll·yaw 를 제외했다. dev10 v2 에서 추종기가 허리 출력을 못 따라간 문제와 같은 방향의 판단이므로, 우리 허리 yaw 는 고정하거나 작은 범위로 묶는다.
  3. 근거 — 몸통(골반) 자세를 상자에 맞춰야 한다: CF-Gen 에서 몸통 적응을 빼면 Carry Box 99.7 → 77.0 %(표 5), 가장 큰 하락. 골반 높이·pitch 를 상자 높이(받침 0/0.1/0.2/0.3 m)와 앞 거리(0.04–0.30 m)에 따라 정하는 것이 손 목표보다 중요하다는 근거.
  4. 가져올 것 — 손 접촉 이진 신호: 추적 목표에 손·발 접촉 비트를 넣자 11.5 → 98.7 %. 우리 teacher 에는 단계 상태기(접근/잡기/들기/유지)가 원하는 접촉 비트를 관측으로 주고, 보상은 exp(−MSE(실제 접촉, 원하는 접촉)) 꼴(손 접촉 = 손–상자 힘 > 5 N)로 줄 수 있다. 실제 접촉 비트는 student 가 못 보므로 critic 전용.
  5. 참고 — 과제약 금지: 관절·전신 목표까지 주면 규칙 생성 목표를 못 따라감(0–0.5 %). 상위가 하위에 줄 명령은 적을수록 좋다는 근거로, 우리도 상체 11 관절을 모두 정밀하게 지정하기보다 손 위치(옆면) 중심으로 보상하고 관절은 명목 + 작은 델타로 둔다.
  6. 참고 — 재계획 감시: 물체 관측과 계획의 편차가 ε 을 넘으면 50 Hz 로 재계획. 나중 운반 단계에서 상자 낙하 시 "다시 접근" 상태로 돌아가는 상태기 규칙으로 쓸 수 있다(낙하 외란에서 92.5 % 회복).
  7. 참고 — DR 값: 몸통 rpy 관측 바이어스 ±5°/±5°/±8°, 1–3 s 마다 ±0.5 m/s 밀기, 관절 강성·감쇠 로그 균일 ×0.75–1.5, 상자 마찰 정 0.5–0.8·동 0.3–0.6, 질량 ×0.5–1.5. 우리 상자 마찰 무작위 범위를 정할 때 하한(동 0.3)이 낮으면 손당 필요 조임이 커진다는 점을 함께 계산한다.
  8. 가져오지 말 것 — MoCap 추적기 학습: CF-Track 은 22 시간 MoCap 으로 전신을 학습하는 하위 정책이다. 우리는 dev12 하체를 고정하므로 이 부분은 대응하지 않는다. AMP 를 추적 0.85 : 스타일 0.15 로 섞는 비율만 참고(스타일이 0.5 이상이면 성공 0 %).
  9. 가져오지 말 것 — 규칙만으로 상위를 대체: CF-Gen 이 잘 된 것은 CF-Track 이 사람 운반 동작을 이미 알고 있어서다. 우리 하위(dev12)는 다리만 알고 손 조작 사전이 없으므로, 규칙 + IK 는 명목 자세로만 쓰고 접촉·조임은 RL teacher 가 배워야 한다.
  10. 비교 수치 해석 주의: 표 2 의 SONIC 3.38 %, HDMI 0 % 는 저자 측정이며 조밀 참조를 규칙으로 합성해 준 조건이다. 우리 dev10 v2(동결 SONIC + teacher)가 teacher 90 % 를 냈던 것과 직접 비교할 수 없다. 우리 상자(37×40.5×29 cm)는 평가 범위(각 변 0.20–0.50 m) 안이다.
