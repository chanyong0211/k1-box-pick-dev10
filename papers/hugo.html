Seoyeon Choi, Shizhao Ye, Nicholas Bui et al. (교신 Negar Mehr) · UC Berkeley, ShanghaiTech, Google DeepMind, Nomagic · 프리프린트 2026-09 (arXiv v2, 2026-09-29) · Unitree G1 · IsaacSim

로컬 PDF arXiv 2609.30594 프로젝트 페이지 유사도 3 코드 미공개
LLM(gpt-5.4)이 과제 설명만 보고 10 차원 명령(기저 3 · 두 손 끝 위치 · 몸 높이)을 내는 폐루프 정책 코드를 쓰고, 롤아웃 수치 요약 + 영상 10 장으로 코드를 고친다. 동결 rl_isaac 위 Lift Box 75.9 %, 같은 명령 공간 PPO(384M 스텝)는 0.0 %. 실기 G1 Lift Box 최고 66.7 %, 상자는 들 때 손 사이에서 미끄러진다.

1. 문제와 과제

과제마다 보상을 짜거나 시연을 모으는 비용을 없애는 것이 목표다 (p.1–2). 상위 정책 π_h 를 과제 설명에서 바로 만들고, 하위 π_l 은 그대로 둔다.

  • 과제 정의 T = ⟨ℓ_task, X, ρ, S⟩: 자연어 설명, 상태 공간(로봇·물체·목표), 초기 상태 분포 ρ(로봇·물체·목표 자세 무작위), 이진 성공 함수 S (p.2–3).
  • 목적: π_h* = argmax E_{x0∼ρ}[S(R(π_h, π_l; x0))] — 기대 성공률 최대화 (p.3).
  • 환경: 실내, 벽이 갈 수 있는 길을 막아 장애물을 고려해야 함 (p.4).

다듬기 알고리즘 (알고리즘 1, p.4)

  1. 프롬프트로 영샷 정책 π_h 생성 → M 초기 상태에서 성공률 s.
  2. 깊이 d = 1…D_max: s = 100 % 면 끝. 아니면 롤아웃 하나를 진단해 피드백 F.
  3. 라운드 r = 1, 2, 3: diff Δ 생성 → 후보 π̃_h 평가 → s̃ > s 면 채택하고 이력 비움, 다음 깊이로.
  4. 실패하면 Δ, s̃, 새 피드백 F̃ 를 문맥에 더해 다른 수정을 시도. 3 라운드 모두 실패면 현재 최고를 반환.
  • 진단(IV-B, p.3–4): 첫 실패 롤아웃을 고름. LLM 이 그 롤아웃 전용 분석 함수 f_analyze 를 코드로 생성 → 전체 궤적에 돌려 요약 D(≤ 200 단어: 거리 극값, 문턱 통과, 추종 오차, 내부 상태 전이)와 키프레임 번호를 냄. 키프레임이 B 보다 적으면 균등 간격 프레임으로 채움.
  • 피드백 LLM 은 롤아웃 하나만 보고, 성공률 숫자는 못 봄 (p.4).
  • 전체 재생성 대신 diff: 잘 되는 논리를 지키고 출력이 짧아짐 (p.4).
  • Best-of-N(IV-D, p.4): 생성이 확률적이라 실행마다 과제 논리가 다름. 다듬기는 처음 논리를 거의 못 바꾸므로 N 번 처음부터 돌려 최고를 고름.

6. teacher → student / 증류

해당 없음 — teacher·student 구조가 없고 상위는 수치 관측(시뮬 상태·모캡)만 쓴다. 저자는 "생성한 정책이 시각 정책을 증류로 감독하거나 RL replay buffer 를 채울 수 있다"를 앞으로의 일로만 적었다 (p.8).

Lift Box 실패 분석 (p.5–6, Remark)

  • 생성 코드가 상자 둘레에 틈을 먼저 만들지 않고 손 끝을 곧바로 쥐는 폭으로 보냄 → 손이 상자 옆면을 쓸고 지나감.
  • rl_isaac 은 추종이 정확해 스치기만 함. SONIC 은 손 끝 추종 오차 4 cm 라 상자를 받침대 밖으로 밀어 냄.
  • LLM 은 상자가 밀려난 것은 보지만 팔 접근 경로 탓으로 돌리지 못해 다듬기가 그곳을 안 고침.
  • 짧은 기하 힌트를 프롬프트에 더하면(인터페이스·하위 그대로) SONIC best-of-10 이 24.9 % → 72.3 %.
  • 두 하위 모두 상자를 쥘 접촉 힘을 못 유지 → 들 때 미끄러짐.

10. 한계

  • 하위 한계를 그대로 물려받음: 두 하위 모두 쥔 물체에 힘을 유지 못 해 LBX·CPB 에서 상자가 미끄러짐 (p.6–8).
  • LLM 이 접촉 실패 원인을 잘 못 짚음: LBX 는 사람이 기하 힌트를 줘야 24.9 → 72.3 % (p.6). 실기 LBX 도 힌트 정책.
  • 물체·목표의 수치 자세가 매 스텝 필요(실기 모캡). 시각 입력 정책은 아님 (p.3, p.7).
  • 생성 결과 편차가 큼: best-of-1 43.9 ± 23.4 %. 30 개 생성 후 고르기가 사실상 필수 (p.6).
  • PPO 기준선의 보상 항·망·RSI·커리큘럼이 안 적혀 있어, "RL 실패"가 얼마나 조정된 RL 인지 알 수 없음 (p.5).
  • 도메인 무작위화·강건성 시험 없음. 실기 시행 수가 작음(정책당 15 회, 다듬기 후보 10 회).
  • 같은 시뮬 성공률(90 %)이 실기에서 93.3 % 와 20.0 % 로 갈림 → 시뮬 순위가 실기 순위를 보장하지 않음 (표 4).

11. 우리에게 가져올 것

  1. 단계 구조를 teacher 에 명시적으로 준다. 같은 명령 공간 · 밀집 보상 PPO 384M 스텝이 LBX 0.0 %, PBX 1.67 % (표 1). 실패 형태가 "작용은 찾지만 접근 · 정렬 · 작용 · 유지 단계는 못 찾음"(p.6). 우리 teacher: 특권 관측에 단계 변수(접근 / 손 벌려 정렬 / 조이기 / 일어서기 / 유지)를 넣고, 단계별 스냅숏 리셋·쪼그림 RSI 로 탐색을 돕는다.
  2. 조이기 전에 틈 먼저. LBX 실패 1 순위가 "손을 곧바로 쥐는 폭으로 보냄 → 옆면 쓸기"였고, 기하 힌트 하나로 24.9 → 72.3 % (p.6). 우리 보상·스크립트에 "두 손바닥 간격 > 박스 폭 + 여유 상태로 옆면 높이까지 내린 뒤에만 간격을 좁힘" 조건을 둔다. 여유는 dev12 + 팔 PD 의 손 위치 추종 오차를 잰 뒤 그 2 배 이상으로(SONIC 오차 4 cm 가 상자를 밀어 냄).
  3. 조임은 명령 채널로 유지. 손 끝 위치만 받는 두 하위 모두 접촉 힘을 못 유지해 미끄러짐 (p.6–7). 우리는 상위가 팔 관절 목표를 직접 내므로(kp 22.3 / kd 1.42) 목표를 박스 안쪽으로 넘겨 PD 조임을 만드는 채널을 그대로 쓰고, 조임 깊이를 행동·보상에 명시한다.
  4. 스크립트 상위 정책을 먼저 만든다(손 코드 또는 LLM 코드). dev12 골반 명령 + 상체 11 로 집기가 표현되는지 확인하는 진단이 되고, teacher 학습의 RSI 상태·시연 공급원이 된다(저자도 증류 감독·replay buffer 시드로 제안, p.8). 단계 변수는 내부 기억이 아니라 관측에서 다시 계산하는 꼴로 써야 DAgger 전문가로도 쓸 수 있다.
  5. 선택용과 보고용 초기 상태를 분리. 다듬기·선택은 고정 100, 보고는 별도 보류 100 (p.5). 체크포인트 고르기와 성공률 보고를 다른 집합으로.
  6. 실기·MuJoCo 후보는 여러 개. 시뮬 90 % 인 두 정책이 실기 93.3 % / 20.0 % (표 4). Isaac 상위 3 개를 MuJoCo sim2sim 과 실기에서 모두 시험한다.
  7. 실기 손 미달을 예상. 실기에서 손 끝이 명령보다 몇 cm 덜 가서 3 cm 안쪽 여유를 더함 (그림 8). 우리 팔은 kp 22.3 에 박스 0.5–2 kg 하중이라 처짐이 생김 → 팔 kp 와 손 하중을 무작위화하고, 실기 bag 으로 조임 시 손 위치 오차를 잰다.
  8. 느린 접근 명령을 따로 잰다. 실기에서 작은 평면 속도 명령 추종이 더 나빴음 (p.7). 박스 앞 미세 위치 맞추기에서 쓰는 작은 vx·vy 구간의 dev12 추종을 Isaac·MuJoCo·실기에서 별도 측정한다.
  9. 진단엔 영상 프레임을 같이. 수치만 보면 LBX 1.4 % vs 영상 포함 35.6 % (표 3). 우리 실패 분석(사람이든 LLM 이든)도 접촉 순간 프레임 + 균등 프레임을 같이 본다.

가져오지 말 것

  • LLM 코드 정책을 최종 상위로 쓰기 — 물체 수치 자세(모캡)가 매 스텝 필요한데 K1 엔 D436 깊이뿐이고, 접촉 실패 진단은 사람 힌트가 필요했다. 우리 목표인 깊이 student 로 가는 길이 아님.
  • 손 끝 위치 명령 인터페이스(몸통·골반 좌표) — 조이는 힘을 표현 못 해 미끄러짐의 원인. 우리 dev12 는 상체 관절 목표를 관측하도록 학습돼 있어 바꾸면 하위 재학습이 필요.
  • "PPO 는 안 된다"는 일반화 — 기준선의 보상·망·RSI 가 공개되지 않았다. 근거는 "탐색 보조 없는 밀집 보상 PPO 는 단계 과제에서 막힌다"까지만.
  • 1.0 m 들기 성공 기준 — G1 기준 값. K1 은 일어서서 유지하는 우리 기준을 쓴다.
  • best-of-30 생성 운영 — LLM 생성의 확률성 때문에 필요한 절차. RL 에선 시드 · 이웃 체크포인트 비교로 대신한다.
