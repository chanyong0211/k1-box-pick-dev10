하체 RL (다리 12) 이 [vx, vy, ωz, 골반 높이] 명령을 따르며 임의로 움직이는 상체를 견디도록, 상체 자세 범위를 넓혀 가는 커리큘럼 + 무릎 높이 보상 + 대칭 손실로 학습 (G1 높이 오차 0.022 m, 20 s 생존 19.95 s). 사람이 페달 (명령) + 동형 외골격 팔 (상체 관절) 로 조종하고, 그 시연 50 개로 학습한 IL 정책이 상체 관절 + 높이를 내어 실기 쪼그려 집기 73.3 %.

1. 문제와 과제

  • 문제 (p.1–2): RL 보행 정책은 환경 적응은 좋지만 정밀 텔레옵용 인터페이스가 없고, 텔레옵 시스템은 상체만 다뤄 이동이 작업 공간에 주는 영향을 무시한다. 기존 분할형 WBC 는 (1) 모캡 동작 사전 의존, (2) 시각 자세 추정의 부정확, (3) 몸 높이 제어 없음, (4) 몸 움직임 기반 이동 명령의 비실용성이 한계.
  • 제안: πloco (하체 RL, 걷기 + 임의 높이 쪼그림, 임의 상체 자세 적응) + 조종석 (동형 7 자유도 외골격 팔, 15 자유도 홀 센서 장갑, 페달). 총 하드웨어 약 $500 (p.2).
  • 명령: Ct = [vx,t, ωyaw,t, ht] (h = 몸통 목표 높이, p.4). 상체 관절 qupper 는 외골격 값을 그대로 로봇에 설정.

2. 시스템 구조

페달 3 개 → [vx, ωyaw, h]→ πloco (HIM 추정기 + 정책), 50 Hz, 관측 6 스텝 이력→ 다리 12 관절 목표 → PD 토크
외골격 팔 (관절 일치) + 장갑→ qupper: 10 Hz 로 전송, 로봇에서 50 단계 보간→ 팔·손 관절 위치 제어
텔레옵 시연 50 개/과제 (RGB + 상태 + 명령, 10 Hz)→ πauto (Seer, 자기회귀 트랜스포머)→ 팔 관절 + 손 + 높이 명령 (10 Hz) → πloco

(p.4, 그림 2–3; p.20, 부록 C, 그림 22) 점선 = 배포 중 고정된 하체 정책.

  • πloco 는 G1 탑재 Jetson Orin 에서 50 Hz (학습과 같은 주기). 조종석 → 로봇은 Wi-Fi TCP, 패킷 128 바이트, 지연 16 ms (p.9, p.20).
  • πauto 는 유선으로 연결된 RTX 4080 호스트에서 추론, 전체 루프 10 Hz (p.20).

4. 보상 · 종료 · 커리큘럼

상체 자세 커리큘럼 (핵심 기법 1)

  • 상체 목표 = 관절별로 행동 최소 또는 최대 쪽 끝값 × 비율 ai. 비율 상한 ρa 를 0 에서 시작해 x 방향 속도 추종 보상이 문턱 (에피소드 평균이 가중치의 80 %, 코드) 을 넘을 때마다 +0.05, 최대 1 (p.5).
  • 표본: ρ′a 를 p(ρ′a|ρa) = 20(1 − ρa) e−20(1−ρa)ρ′a / (1 − e−20(1−ρa)) 에서 뽑고 ai ∼ U(0, ρ′a) (식 2–3). ρa 가 작을 땐 0 근처에 몰리고 1 에 가까워지면 U(0, 1) 이 된다 — 처음부터 전 범위에 0 이 아닌 확률.
  • 상체 목표를 1 s 마다 다시 뽑고, 1 s 동안 균등 (선형) 보간. 보간이 없으면 균형을 못 잡았다 (p.5). 코드: upper_interval_s = 1, 스텝마다 (목표 − 현재)/50 씩 이동.

높이 추종 보상 (핵심 기법 2)

  • rknee = −‖(hr,t − ht) × ((qknee,t − qknee,min)/(qknee,max − qknee,min) − 1/2)‖ (식 4). 실제 높이가 목표보다 낮으면 무릎을 펴고, 높으면 굽히도록 유도.
  • 기저 높이 추종 = exp(−4|ht − hr,t|), 높이는 골반과 두 발 중 높은 쪽 차로 계산 (코드 _reward_tracking_base_height).

대칭 활용 (핵심 기법 3)

  • 모든 전이 Tt 를 x-z 평면에 대해 뒤집어 T′t 도 저장 (데이터 증강) + 학습 때 Lsymactor = MSE(at, a′t), Lsymcritic = MSE(Vt, V′t) (식 5–6). 코드: use_flip = True, symmetry_scale = 1.0 (him_ppo.py).

10. 한계

  • 저자 언급 (p.11): 다양한 지형 통과 신뢰성 부족, 장갑 엄지 설계, 힘 피드백 없음, 허리 텔레옵 없음.
  • 하체가 쪼그린 채 걷기를 학습하지 않았다 (코드). 높이 명령은 정지 중에만 바뀐다.
  • 상체 목표 자체를 관측하지 않아, 상체가 빠르게 움직일 때 하체가 미리 대비할 신호가 없다 (구조상 판단).
  • 손 하중 −0.1–0.3 kg 은 작아 무거운 물체 근거가 되지 못한다. 몸통 하중 −5–10 kg 은 크다.
  • IL 성공률의 시도 수가 없고, 상위가 사람·IL 이라 RL 상위와의 결합 결과는 없다.
  • 논문 표와 코드가 다른 곳: 명령에 vy 포함 여부 (본문 Ct 3 개 대 코드 4 개), 마찰 상한 2.0 대 3.0, 쪼그림 범위 표기, 배포 PD.

11. 우리에게 가져올 것

  1. dev12 점검 1 — 쪼그린 채 걷기: HOMIE 는 쪼그림 1/3 · 서기 1/6 · 걷기 1/2 로 나누고 쪼그림 중 속도 0 이었다. dev12 는 걷기 높이 0.42–0.77 m 를 요구하므로 이 조합이 실제로 학습 분포에 충분히 있는지 확인 (dev10 의 접근·운반 단계가 쓰는 영역).
  2. dev12 점검 2 — 상체 무작위 분포: HOMIE 는 1 s 마다 관절 한계 끝값 × 비율로 목표를 뽑고 1 s 선형 보간, 비율 상한을 식 2–3 커리큘럼으로 0 → 1. 상위 RL 이 낼 상체 변화 (특히 박스를 향해 두 팔을 앞·아래로 뻗는 자세 + 허리 yaw) 가 dev12 학습 분포 안인지, 변화율이 dev12 가 본 범위 안인지 비교한다. 밖이면 상위 증분 배율을 그 안으로 묶는다.
  3. 상위 출력 = 상체 + 높이: HOMIE IL 의 회귀 머리는 팔·손·높이 셋이었고 쪼그려 집기 73.3 %. 우리 상위가 골반 높이와 상체를 함께 내는 설계의 실기 선례로 쓸 수 있다. 쪼그림·조이기 단계에선 속도 명령을 0 으로 묶는 것도 HOMIE 하체 분포와 같은 꼴.
  4. 상위 주기와 보간: HOMIE 실기는 상위 10 Hz + 로봇 쪽 선형 보간 (50 단계). 우리 상위를 50 Hz 증분으로 내더라도, dev12 가 보는 저역 통과 목표의 변화율이 학습 분포 안에 머무르도록 같은 역할의 필터를 상위 출력 뒤에 둔다.
  5. 높이 추종 무릎 보상 rknee (가중치 −0.75): dev12 를 다시 학습할 때 낮은 높이 (0.335 m) 수렴이 느리면 높이 보상 배율을 키우기보다 이 항을 쓴다 — 배율만 키우면 속도 추종이 크게 나빠졌다.
  6. 대칭 = 증강 + 손실 둘 다 (계수 1.0): 증강만 쓰면 대칭 손실이 컸다. dev12·상위 teacher 모두 좌우 거울 (두 손 조이기는 대칭 과제) 에 쓸 수 있다.
  7. "Action vanish" 벌점 (−1.0): 행동이 자르기 범위를 넘은 양에 선형 벌점. v2 의 "환경 안 자르기 → std 발산" 대책과 같은 꼴을 하체 쪽에서 이미 쓰고 있다.
  8. 발목 Kp 를 낮추면 정지·이동 전환이 안정 됐다는 관찰: K1 실기 한 발·정지 흔들림 문제와 같은 축의 실험 근거로 기록해 둔다.

가져오지 말 것

  • 손 하중 범위 −0.1–0.3 kg: 우리 박스 0.5–2 kg 와 조이기 반작용엔 턱없이 작다. dev12 의 0–5 kg 가 맞다.
  • 상체 목표를 관측하지 않는 하체: dev12 는 목표와 변화율을 보는 쪽이 이미 앞서 있다. 되돌리지 않는다.
  • HIM 추정기·Isaac Gym 코드: 우리는 Isaac Lab + Newton + rsl_rl. 구조 이식 가치가 작고, 라이선스도 비상업 (CC BY-NC / NC-SA).
  • 사람 텔레옵 → IL 상위: 우리 상위는 RL + 깊이 student. 시연 수집 장비가 없다.
  • 몸통 pitch 없는 명령 공간: 바닥 박스에는 숙임 (pitch) 이 필요하다 (K1 은 숙여야 최저 자세가 나옴).
