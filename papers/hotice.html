HOTICE: 장애물 사이로 물체를 든 채 지나가는 휴머노이드 전신 운반

HOTICE: Whole-Body Humanoid Object Transportation in Cluttered Environments

Toan Nguyen, Weiduo Yuan, Siheng Zhao, Yue Wang, Daniel Seita · University of Southern California · 사전 공개 (arXiv 2026-09-21) · Unitree G1 · MuJoCo (MuJoCo Playground)

로컬 PDF arXiv 2609.25363 프로젝트 페이지 유사도 3 논문만 (코드 없음)
G1 이 이미 든 상자를 옆·머리 위·바닥 장애물 사이로 목표까지 옮긴다. 장애물 회피 안내 벡터장(HOD-PF)을 관측과 보상에 넣고, 다리 12 / 팔 8 을 두 에이전트 PPO 로 나눠 학습한 뒤, 장면별 teacher 들을 DAgger + PPO 로 student 하나에 모았다. 시뮬 성공 88.5 % (한 에이전트 65.7 %), 실기 장애물 유형별 6/6 · 5/6 · 5/6.

1. 문제와 과제

  • 장애물 C 가 있는 장면에서 로봇은 시작점 s ∈ R³ 에서 물체 O 를 든 채 출발해 목표 g ∈ R³ 까지 옮긴다. 장애물은 세 종류: 옆(side), 머리 위(overhead), 바닥(ground) (p.2, 그림 1).
  • 물체는 주로 직육면체 상자. 원통·구로도 일반화 실험 (p.6–7).
  • 논문 설명과 실험은 상자를 이미 들고 시작한다고 가정. 전체 파이프라인용으로 받침에서 집는 정책도 학습했다고만 쓰고 세부는 없음 (p.2).
  • 성공: 5 s 안에 목표 0.1 m 이내 도달, 넘어짐·떨어뜨림·충돌(로봇 또는 상자) 없음. 실패: 넘어짐, 떨어뜨림, 충돌 중 하나 (p.2, p.6).
  • 지표: 성공률 SR, 끝 시점 루트–목표 평균 거리 mDist (p.6).
  • 상자 질량·크기는 무작위, 상한 3.5 kg · 40×40×40 cm³. "G1 의 하중·크기에 맞추고 극한 장면에서도 통과 가능하도록" 정한 값 (p.5).

HOD-PF 계산

  • 끌림 퍼텐셜 U_att(x) = η · D_geo(x, g). D_geo = 장애물을 피해 가는 최단 경로 길이 (식 1).
  • 밀림 퍼텐셜 U_rep(x) = ½ ξ (1/sdf(x) − 1/d₀)² (sdf(x) ≤ d₀ 일 때), 아니면 0 (식 2).
  • F_standard(x) = −∇ₓ(U_att + U_rep) (식 3). 목표로 당기고 장애물에서 밀어냄.
  • OGF 는 장애물을 여유 m 만큼 부풀린 C_inflated 로 같은 계산. 이유 둘: 상자는 관절로 직접 구동되지 않아 실기 잡음·지연에 여유가 필요, 무거운 물체는 가까이 가서 피하기 어려우니 미리 피하게 (p.4, 그림 3).

행동

  • a_low ∈ R¹² (다리 관절), a_up ∈ R⁸ (팔 관절), 이어 붙여 20 차원 → PD 제어기 → 토크 (p.4).
  • 허리·손목 관절은 "이 설정에서 불필요"해서 제외 (p.4). G1 팔 7 관절 중 손목 3 을 빼면 어깨 3 + 팔꿈치 1 = 팔당 4 로 보임 (추정).
  • PD 이득, 행동 배율, 행동 범위: 논문에 없음.

4. 보상 · 종료 · 커리큘럼

보상 묶음과 두 흐름

묶음들어가는 항받는 쪽
L (하체)보행, 균형lower
U (상체)물체 도달, 잡기 유지upper
S (공유)물체 들기, HOD-PF 보상 ("팔 관절과 몸통 자세가 함께 정하는 값")둘 다
  • r_low = Σ_{i∈L∪S} wᵢ rᵢ, r_up = Σ_{i∈U∪S} wᵢ rᵢ (식 4). 각 항의 식과 가중치 wᵢ 는 논문에 없음.
  • 공유 항이 두 흐름에 다 들어가 둘 다 운반에 책임을 지고, 보행 신호와 잡기 신호가 한 이점 추정 안에서 다투지 않는다는 것이 설계 이유 (p.4).

HOD-PF 보상 (식이 주어진 유일한 항)

  • SGF: 머리·골반·발의 위치 x, 속도 v 에 대해 cos(F_standard(x), v) 최대화 (p.4).
  • OGF: 손과 상자 키포인트에 대해 cos(F_object(x) − c, v − c) 최대화. c = 머리·골반·발 SGF 벡터를 모은 "전체 이동 명령". c 를 빼서 보행이 이미 만드는 움직임은 제외하고, 손이 실제로 책임지는 장애물 회피 조정에만 점수를 준다 (p.4).

종료 · 커리큘럼

  • 종료: 두 에이전트가 같은 종료 조건을 공유한다고만 씀. 구체 조건은 논문에 없음. 과제 실패 정의는 넘어짐·떨어뜨림·충돌 (p.2, p.4).
  • 커리큘럼: 언급 없음. 장면별 보상 조정도 하지 않음 ("안내장이 일반화되는 표현이자 보상 구조") (p.5).
  • 원통·구 정책은 손 위치·물체 직립 보상만 조금 바꾸고 나머지 항·가중치·하이퍼파라미터는 상자 정책 그대로 (p.6).

6. teacher → student / 증류

  • teacher: 장면마다 하나, 잡음·지연 없는 특권 상태로 학습 (p.4).
  • student: 일반 정책 하나. DAgger 로 teacher 들을 증류한 뒤, teacher 와 같은 두 에이전트 구조로 PPO 를 더 돌려 다듬음. 이때 센서 잡음·제어 지연을 시뮬 (p.5).
  • student 입력: 고유감각 + 물체 상태 + HOD-PF 벡터 (그림 2). 즉 student 도 상태 기반이고, "보이는 것"의 차이는 잡음·지연뿐이다. 영상 student 가 아님.
  • DAgger 만 vs DAgger + PPO 비교, teacher 대비 student 성공률 차이는 보고하지 않음.

8. 실기 · sim2real

  • 로봇: Unitree G1. 장면은 상자 없이 로봇을 걸려 SLAM(FAST-LIO2)으로 미리 재구성 (p.6).
  • 추론 때 HOD-PF 벡터는 실시간 위치 추정 + 관절각으로 계산, 상자 자세는 AprilTag + 머리 카메라 (p.6–7).
  • LiDAR 로 실시간 재구성도 원리상 가능하지만 G1 의 LiDAR 하나가 든 상자에 크게 가려짐 → 하드웨어 한계라고 설명 (p.7).
  • 시행: 매 시행 공용 집기 정책이 받침에서 상자를 집고 나서 운반 정책이 이어받음. 둘 다 50 Hz. 장애물 유형마다 방법별 6 회 (p.7).

10. 한계

  • 저자 언급: 충돌 이후 상황을 모형화하지 않아 큰 충돌이면 넘어짐. 어깨에 메기·허리에 끼기 같은 복잡한 조작은 못 함. 움직이는 장애물 없음. 기대기·부드러운 물체 스치기 같은 "허용 충돌"은 다루지 않음 (p.8).
  • 재현에 필요한 값이 대부분 빠짐: 보상 항별 식·가중치, 망 크기, PPO 하이퍼파라미터, 무작위화 범위, env 수, 종료 조건.
  • 집기 정책은 존재만 언급. 우리 과제(집기)에 대한 직접 근거는 없음.
  • student 도 상태 기반이고 실기에 SLAM 지도 + AprilTag 가 필요. 영상 student 의 격차 문제는 다루지 않음.
  • DAgger 뒤 PPO 의 효과, teacher–student 격차 수치가 없음.
  • 실기 시행 수가 유형당 6 회로 작음.

11. 우리에게 가져올 것

  1. 상자 꼭짓점 8 개를 teacher 관측에. 상자 중심·자세 대신(또는 함께) 골반 좌표계 꼭짓점 8 개(24 값)를 넣는다. 37×40.5×29 cm 상자의 옆면 위치가 바로 드러나 손바닥 목표를 정하기 쉽고, student 가 깊이에서 추정할 보조 목표로도 쓸 수 있다. HOTICE 는 모양이 바뀌어도 키포인트 8 개로 관측 배치를 고정했다 (p.6).
  2. "기저 움직임을 뺀 잔차"에만 손 보상. HOTICE 의 OGF 보상은 이동 명령 c 를 빼고 손의 추가 움직임만 평가한다 (p.4). 우리에선 손바닥 접근 보상을 손 속도 그대로가 아니라 골반 속도를 뺀 상대 속도(또는 골반 명령이 만드는 몫을 뺀 값)로 계산해, 골반을 숙여서 얻은 접근과 팔이 만든 접근을 가른다 (추론, 우리 적용안).
  3. 보상 흐름 분할은 2순위 실험으로. 한 정책으로 상체 11 의 조이기 항과 골반 명령의 자세 항이 서로 다툴 때(dev10 v2 의 한 손 밀기처럼) 시도할 가치가 있다: upper 헤드 = 손바닥 거리·두 손 접촉·조임 항, pelvis 헤드 = 높이·pitch 추종·명령 변화율 항, 공유 = 상자 높이·직립·성공. 근거는 +18.4–22.8 %p (표 I). 다만 rsl_rl 기본 ActorCritic 은 critic 하나라 구현 비용이 있으니 단일 정책 기준선이 막힐 때만.
  4. 불필요한 관절은 뺀다. HOTICE 는 허리·손목을 뺐다 (p.4). dev10 v2 에서 추종기가 못 따라간 것이 허리였으므로, 첫 teacher 는 허리 yaw 고정(상체 출력 10)으로 시작하고 상자 yaw ±40° 구간 성공률이 떨어질 때만 좁은 범위로 연다 (우리 적용안).
  5. 평가 규약. "시간 안 목표 도달 + 넘어짐·떨어뜨림 없음" 이진 성공, 조건별 1,000 회, 평가에 잡음·지연·외란을 넣음 (p.5–6). 우리는 받침 높이 0/0.1/0.2/0.3 × yaw × 옆 오프셋 격자로 같은 표를 만든다.
  6. student PPO 미세조정의 또 하나의 선례. DAgger 뒤 같은 구조로 PPO (p.5). 다만 이 논문은 효과 수치를 주지 않으므로 근거로는 약하다 (DoorMan·PRISM 쪽 숫자를 근거로 쓸 것).

가져오지 말 것

  • HOD-PF 안내장 자체: 집기 과제에는 장애물이 없다. 나중에 어수선한 곳을 들고 지나갈 때만 의미가 있고, 그때도 상자 부풀림 여유 8 cm 정도만 참고.
  • 장면별 teacher 여러 개 → 증류: 우리 장면 변화(상자 자세 + 받침 높이 4 단계)는 작아 teacher 하나로 충분할 것이다. 받침 높이별 teacher 는 하나로 안 될 때의 대안.
  • 다리 관절 직접 제어: 우리는 dev12 를 동결해 두는 설계다.
  • SLAM 지도 + AprilTag 실기 구성: 우리는 머리 D436 깊이 student 로 간다.
