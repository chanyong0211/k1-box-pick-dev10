1. 문제와 과제

  • 과제: "Drop the blue cube into the green basket." 같은 지시를 받아 물체 A 를 찾아 집고, 바구니 B 를 찾아가 넣는다 (p.7).
  • 부분 관측: 카메라는 손목 RGB 하나. 작업 공간 대부분이 대개 시야 밖이다 (p.3).
  • 긴 과제의 두 난점 (p.5): ① 병목 상태(작은 물체 집기)를 지나야 다음이 열리는 "계속 탐색" 문제, ② 학습이 길어지며 생기는 용량 손실·파국적 망각.
  • 장면: 로봇은 2 × 2 m 정사각형 가운데, 물체·바구니는 네 모서리. 학습 때는 각 모서리 둘레 반지름 0.5 m 원 안에서 무작위 (p.10, 그림 7). Cluttered 배치(앞뒤로 몰아 둠)는 분포 밖 평가용.

2. 시스템 구조

학습은 세 단계를 차례로 하고, 앞 단계 결과는 다음 단계에서 고정한다 (p.4, 그림 2).

학습 순서

① 하위 보행 PPO
명령 (vx, ωz) 무작위 + 팔 관절 무작위 구동→ 고정 → ② 상위 teacher SAC
하위 과제 id + 물체 특징 (Progressive PEX)→ 고정 → ③ 상위 student SAC
과제 보상 + teacher KL + 분할·깊이 예측 손실

배포 (실기)

언어 지시 + 손목 RGB 5 장 (160×90, 60 FPS 촬영) + 고유감각 5 스텝→ student 상위 10 Hz
(노트북 RTX 3070 Ti)→ 팔 Δ 6 + 그리퍼 1 → 팔 PID 드라이버 (약 500 Hz)
student 의 보행 명령 c (vx, ωz)→ 동결 보행 정책 50 Hz
다리 관절 위치만 관측→ 다리 12 관절 PD 목표

점선 = 고정. 상위·하위는 비동기로 돌려, 상위 추론이 늦으면(20 ms, 가끔 40 ms) 하위는 직전 명령을 계속 쓴다 (p.22).

  • 전제: 보행 명령만 주면 보행 제어는 상위 과제 의미와 거의 독립 (p.4).
  • 팔은 관절 공간으로 직접 제어 — IK 를 쓰지 않으려고 (p.5).
  • 상위 보상 = 재계획 주기 5 하위 스텝의 보상 합 (p.17, 식 3).
  • 모델 크기: 하위 3M, teacher 전체 10M, student 16M, 배포(하위 + student) 19M 미만 (p.20, 표 VIII).

행동 사전 (behavior prior) (p.16–17)

  • 정지 조작: Grasp · MoveGripperToWithObj · DropInto 에서 보행 명령 c = 0.
  • 회전 탐색: Search · SearchWithObj 에서 전진 c[0] = 0 (작업 영역 밖으로 걸어 나가지 않게).
  • 구현: 해당 하위 과제의 teacher 출력 분포 평균을 해당 차원에서 0 으로 초기화(분포 자체는 남겨 KL 계산이 일관되게). teacher 는 argmax 로 정확히 0 을 낸다 (p.17, p.19).

종료 · 커리큘럼

  • 상위 에피소드: 하위 과제 실패 시 −1 과 함께 종료로 읽히나 실패 조건 목록은 논문에 없음. 평가 시간 제한 90 s (p.9).
  • 명시적 난이도 커리큘럼은 없음. 대신 Progressive PEX 가 새 하위 과제에 처음 도달할 때마다 새 망을 붙이는 것이 사실상 커리큘럼 (p.5).
  • teacher 팔 제어 잡음: ±0.02 → 3M 반복 뒤 ±0.05 로 키움 (p.20).
  • student 롤아웃 비율 β: 0.5 유지 → 750K 반복부터 선형 증가 → 1.25M 반복에 1.0 (p.20).

6. teacher → student / 증류

teacher: Progressive PEX (p.5–6, 식 1, 그림 3)

  • teacher Π = {πk}, 하위 과제마다 구조가 같은 망(actor + critic) 하나. 처음엔 π1 만 있고, 새 하위 과제에 처음 도달할 때마다 새 망을 추가.
  • 순전파는 하위 과제 id 로 고른 망만: Π[k] ≡ πk. 배치의 각 표본은 자기 하위 과제 망만 학습시킴 (다중 과제 SAC).
  • 효과: 새 단계는 늘 "새 망"으로 탐색을 시작(가소성 유지), 이미 배운 단계 망은 건드리지 않음(망각 방지).

student: 증류 유도 RL (p.6, 식 2)

max_π  E_(s_stu, s_p, k)∼D_replay [ E_a∼π_stu(·|s_stu) Q(s_stu, a)  −  α · KL( π̃_tea^k(·|s_r, s_p) ‖ π_stu(·|s_stu) ) ]
s_stu = [o, s_r, l],   α = 0.01,   π̃_tea = teacher 분포의 최빈값은 그대로 두고 분산만 σ = 0.05 로 고정
  • 혼합 롤아웃: 에피소드 시작마다 확률 β 로 그 에피소드 전체를 student 가, 아니면 teacher 가 행동. teacher 궤적은 student 가 아직 못 가는 뒤쪽 하위 과제까지 replay 를 채우고, student 궤적은 자기 탐색을 줌. β 0.5 → (750K–1.25M 반복 선형) → 1.0 (p.6, p.20).
  • 엔트로피 제거: 정책 평가의 엔트로피 보상(SACLite)과 정책 개선의 엔트로피 항을 모두 빼고 그 자리에 KL 을 넣음. 고정 σ 가 탐색 폭을 대신 정함 (p.6).
  • 정지 비트: teacher 의 c 는 argmax 가 정확히 0 이지만 연속 분포 증류로는 0 최빈값을 보장 못 함 → student 에 이진 분포 출력을 추가해 "teacher c 가 정확히 0 인가"를 예측 학습, 참이면 보행 명령 두 차원의 KL 을 가리고, 추론 때 1 이면 c 를 0 으로 덮어씀 (p.19).
  • 보조 지도 손실: 분할·깊이 예측 (정답은 시뮬에서 공짜) (p.6).
  • DAgger 아님: teacher 는 replay 표본에 대해 KL 목표만 주고, student 가 SAC 로 과제 보상도 직접 최대화.

"증류 없이 RL 만"(시각 student 를 처음부터 RL) 은 시뮬에서도 과제를 전혀 못 풀어 결과표에서 뺐다 (p.9, 각주 3).

  • 하드웨어: Go1 + 위에 단 WidowX-250S, 손목에 3D 프린트 마운트로 RealSense D435 (RGB 만). 그리퍼 손가락을 길게 3D 프린트하고 안쪽에 얇은 폼(마찰↑). 팔 받침 50 mm 높임. 개발판 기준 약 $12K (p.8–9).
  • 계산: 노트북 i9-12900H + RTX 3070 Ti 노트북 GPU + 16 GB. 상위 10 Hz · 하위 50 Hz 비동기, Raspberry Pi 의 팔·보행 드라이버 약 500 Hz. 카메라 60 FPS 424×240 → 160×90 (p.9).

안전 조치 (p.23, 부록 F-B)

  1. 팔만 따로(탁상 정책), 사족만 따로(팔 없이) 먼저 sim2real 을 맞춘 뒤 합침.
  2. 팔 PID + 작은 증분 z = 0.05 → 팔 기어 손상이 크게 줄었음.
  3. 모터 세기·하중·질량 중심·팔 장착 무작위화 덕에 팔이 바닥·물체를 밀어붙이지 않음.
  4. 상위 추론이 40 ms 를 넘을 때가 있어 상·하위 비동기 실행 (동기면 넘어질 수 있음).
  5. 버튼 하나로 종료, 지연 급증·네트워크 끊김 시 Go1 드라이버가 스크립트 정책으로 자동 정지.
  6. 회전 탐색 사전으로 작업 영역 밖으로 걸어 나가지 않게.
  7. 초기엔 목줄, 정책이 믿을 만해진 뒤 제거.
  8. 카메라 마운트는 옆으로 넘어질 때 먼저 부러지게 설계.
  9. Go1 모터 온도를 자주 확인 — 과열 모터는 위험한 보행을 낸다.

11. 우리에게 가져올 것

  1. 집기 단계는 골반 속도 명령을 아예 0 으로 묶는다 (SLIM "정지 조작", 중요도 ★★★). pelvis_pick 첫 단계(접근 없음)에선 vx·vy·ωz 를 상위 출력에서 빼고 높이·pitch(·roll)만 낸다. 나중에 접근·운반을 붙일 때는 SLIM 의 "정지 비트"(이진 출력이 1 이면 속도 명령을 정확히 0 으로 덮어씀)를 student 에 그대로 쓴다 — 가우시안 증류로는 0 을 정확히 못 낸다는 이유가 우리 DAgger 에도 똑같이 적용된다.
  2. 상체 출력은 작은 유계 증분: SLIM 은 팔 관절 Δ ∈ [−0.05, 0.05] / 10 Hz 스텝(= 0.5 rad/s), squashed Gaussian(SAC) 또는 Beta(형상 ≥ 1, 하위 PPO). 우리 상위 주기에 맞춰 같은 rad/s 로 환산(50 Hz 면 스텝당 0.01 rad)하되, 박스로 손을 옮기는 데 필요한 속도를 먼저 재고 정한다. v2 의 온오프 포화와 "환경 안 자르기 → std 발산"을 함께 겨냥하는 처방이다. rsl_rl 의 Beta 분포 지원 여부는 우리 버전에서 확인 필요.
  3. teacher 의 박스 관측을 D436 시야와 맞춘다: SLIM 은 물체가 카메라 시야 밖이면 teacher 특징을 0 으로 둬 "보이는 것"을 student 와 같게 했다. 우리는 26×64 크롭 시야(목 아래 47° 에서 행 400–479 가 머리 커버에 가린다는 실측 — D436 기준표 §5)에 박스 꼭짓점이 몇 개 드는지로 가시성 마스크를 만들어 teacher actor 의 박스 자세를 가린다(가린 동안은 마지막으로 본 값 유지 여부도 함께 실험). v2 student 격차를 "접촉 정보"로 돌렸지만, 쪼그려 가까이 갔을 때 박스가 시야를 벗어나는 격차도 같은 꼴이다(추론).
  4. student 에 RL 항 + teacher KL: 실기 78.3 % 대 증류만 50.0 %. PPO 로 옮기면 "PPO 손실 + α · KL(π̃teacher ‖ πstudent)", α = 0.01, teacher 분산은 σ = 0.05 로 고정(최빈값만 따라가게)이 출발값. teacher/student 롤아웃 비율은 β = 0.5 로 시작해 후반에 1.0.
  5. "들고 있을 자세" 보상 (arm-retract 대응): SLIM 은 이것 하나 빼서 실기 78.3 → 5.0 %. 원인은 뻗은 팔 → 토크 한계 근처 → 떨림·미끄러짐. 우리 v2 는 박스를 팔 끝에 매달고 15 cm 폭으로 흔들었다(내부 기록). 들기 성공 뒤 상체 관절을 "박스를 몸통 가까이 든 중립 자세"로 끌어오는 거리 감소량 보상을 둔다.
  6. 물체 교란(★★★): SLIM 은 단계 도중 물체를 반지름 10 cm 안으로 순간이동(2.5 cm 물체 기준). 우리 v2 의 "체크포인트마다 성공률 출렁임"과 한 궤적 외우기를 줄이려면, 손이 닿기 전 접근·쪼그림 단계에서 박스를 몇 cm·몇 도 옮긴다(크기는 박스 37 cm 에 맞춰 새로 정할 것 — SLIM 값 그대로 아님).
  7. 두 손이 반대편에 오게 하는 정렬 항: SLIM 의 alignment = 왼·오른 손가락 끝 → 물체 벡터 사이 코사인. 우리는 왼·오른 손바닥 → 박스 중심 벡터가 박스 좌우 옆면 법선과 반대 방향인지로 바꿔, 한 손 밀기 국소해를 직접 깎는 항으로 쓴다(가중치는 논문에 없음).
  8. 지연 DR 의 구조: "에피소드 평균 + 스텝 흔들림"(모터 센서 U(3, 13) ms ± 2 ms), 카메라는 스텝마다 U(30, 50) ms. 값은 우리 실측(D436 가장 최근 프레임 나이 14–45 ms, 실기 관절 추종 ≈ Isaac + 5–15 ms)으로 바꿔 넣는다.
  9. 하위 정책 고를 때 "떨림"을 본다: SLIM 은 하위 시드 10 개 중 정지 전환이 가장 덜 떨리는 3 개만 썼다. dev12 를 동결하기 전에 쪼그림 ↔ 서기, 걷기 → 정지 전환에서 골반 각속도·발 미끄럼을 재서 고른다.
  10. 평가 규약: 단계별 누적 성공률(접근 → 두 손 접촉 → 들기 → 유지)을 표로, 시드 여러 개, 시간 제한을 실패로 셈. 시각 증강을 뺀 정책이 시뮬에서 더 높게 나온 사례가 있으니 체크포인트 선택은 잡음 켠 평가로.

가져오지 않을 것

  • SAC + replay, 60–120 env, 1–2 주: 우리 Isaac Lab PPO(수천 env) 파이프라인과 맞지 않는다. 핵심(KL 항, 혼합 롤아웃, 고정 σ)만 PPO 에 옮긴다.
  • Progressive PEX (하위 과제마다 망): 지금 과제는 쪼그림 → 조이기 → 들기 → 유지로 짧고, student 가 단계 id 없이 하나로 흉내 내야 한다. 단일 teacher 가 두 손 접촉 병목에서 정체할 때만 다시 볼 것.
  • 하위에서 상체 관측 숨기기: SLIM 은 팔 관측을 빼서 실기 떨림을 줄였지만, dev12 는 상체 목표·변화율을 보는 것이 설계 전제다. 실기에서 정지 전환 떨림이 보일 때 비교 실험 후보로만 남긴다.
  • 팔 PID 로 추종 오차 0: 우리는 조이기 힘을 PD 추종 오차로 만든다(kp 22.3). 오차 0 은 목표가 될 수 없고, K1 드라이버가 PID 를 지원하는지도 확인 전이다.
  • RGB U-Net 분할·깊이 병목, 언어 인코더: 우리는 처음부터 깊이를 쓴다. 대신 "보조 예측 헤드"라는 생각만 — 박스 위치·두 손 접촉 여부 예측으로.
  • 보행 걸음새 보상·trot 고정: 사족 전용.
