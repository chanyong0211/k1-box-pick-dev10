1. 문제와 과제

  • 문제 의식 (p.1–2): 휴머노이드 RL 의 병목은 시뮬 속도·알고리즘이 아니라 검증·학습·평가·배포를 잇는 체계가 없다는 것. (i) 작업 흐름 격차: 관절 축 반전·보상 오류를 긴 학습 뒤에야 발견, 확률적 롤아웃만으론 관절 한계 위반·고주파 구동을 진단하기 어려움. (ii) 이전 격차: 관절 순서·관측 이력·행동 배율을 손으로 맞추다 생기는 조용한 버그.
  • 4 단계 (p.2, 그림 1): ① 준비 (관절 GUI, 물체 GUI, 보상 시각화) ② 학습 (git 스냅숏·설정 덤프, 스윕) ③ 평가 (결정적 시나리오 + 확률 롤아웃, 동작 품질 지표, HTML 보고서) ④ 배포 (TorchScript + YAML I/O 기술자, MuJoCo sim2sim).
  • 검증 과제 5 개 (p.3, 표 2): 속도 추종 (G1·T1), 속도 + 높이 보행 (G1), 일어서기 (G1·T1), 동작 모방 (G1 춤), 이동 조작 + VLA (G1 집어 놓기).

2. 시스템 구조

상위 RL 정책 (집어 놓기 전문가)→ 상체 증분 × 0.05 → 이전 목표에 더하고 관절 한계로 자르기→ 오른팔·손·허리 PD
같은 정책의 하체 명령 4 [vx, vy, ωz, 높이]→ 명령별 clip (집어 놓기: vx −0.2–0.5, vy ±0.4, ωz ±0.5, 높이 0.65–0.72)→ AgileBasedLowerBodyAction: TorchScript 속도·높이 teacher (고정)→ 다리 12 관절 목표 (× 배율 + 기본 자세)
전문가 성공 궤적 100 개 (타일 렌더, 시각·물리 무작위)→ GR00T N1.5 VLA 미세조정 (RGB + 언어)→ VLA 가 상체 목표, 동결 하체가 균형

점선 = 고정. 50 Hz 제어, 물리 200 Hz (코드 decimation 4, dt 0.005). (p.7 그림 3, p.10–11 4.5절·그림 5; pick_place_tracking_env_cfg.py)

행동 항 안에서 무슨 일이 일어나나 (코드)

  1. 환경의 행동 관리자가 정책 출력 벡터를 행동 항 순서대로 나눈다: upper_body_joint_pos (상체 증분) 다음 lower_body_joint_pos (4 차원).
  2. AgileBasedLowerBodyAction.process_actions (env 스텝마다 1 회, 50 Hz): 4 명령을 torch.clamp 로 자름 → 하체 정책용 관측 그룹 agile_policy 를 env 의 관측 버퍼에서 꺼냄 → 명령을 이력 길이만큼 반복해 앞에 붙임 → torch.inference_mode() 로 TorchScript 실행 → 관절 행동 × 배율 + 기본 관절 위치.
  3. apply_actions (물리 하위 스텝마다): 다리 12 관절 목표를 그대로 적용.

(policy_actions.py, 180 행) 하체 관측 그룹은 선속도·각속도·중력·전체 관절 위치·속도·직전 행동 (속도·높이 teacher 관측과 같은 꼴). 자르기 밖으로 나간 양에 대한 벌점은 없다.

6. teacher → student / 증류

  • 하체: 특권 teacher (기저 선속도 + 발 높이 스캔 critic) → 순환망 student 와 이력 MLP student 로 증류 (p.9). 코드: RslRlDistillationAlgorithmCfg, MSE, 에폭 5, gradient_length 15, lr 1e-3, 최대 5,000 반복, student [256, 256, 128], 이력판은 대칭 거울 손실 켬.
  • 상위: 특권 RL 전문가가 성공 궤적 100 개를 타일 병렬 렌더로 생성 (물리·시각 무작위) → RGB + 고유감각 + 행동 쌍 → GR00T N1.5 를 언어 과제 설명과 함께 미세조정. 배포 때 VLA 가 상체 목표, 동결 하체가 균형 (p.10–11).
  • 집어 놓기 시연 수집 시 하체에 쓰는 것은 teacher TorchScript (unitree_g1_velocity_height_teacher_torchscript.pt) 로, 기저 선속도 같은 특권 관측을 그대로 받는다.

7. 결과

  • 집어 놓기 VLA: 무작위 초기 로봇 상태 100 회 시뮬 폐루프에서 90 % 성공 (p.11). RL 전문가 자체의 성공률은 논문에 없음.
  • 높이 추종 (그림 4, MuJoCo): 높이 0.4–0.7 m 계단 훑기를 따라감, 높이 오차 0.035–0.046 m (표 3).
  • 평가 파이프라인 관찰: Isaac Lab 에서 관절 한계를 계속 어기는 정책은 sim2sim 이 거의 항상 실패 → 그 신호로 미세조정 후 MuJoCo 로 넘김 (p.9).
  • 절제 요약 (그림 6, 7, 5 시드): 보상 정규화는 1 배에선 작은 이득·100 배에선 회복, 가치 부트스트랩은 분산 감소, 하네스는 빠른 수렴, 대칭은 작은 보상 이득 + 행동 대칭, L2C2 는 네 지표 모두 감소.

8. 실기 · sim2real

  • 다섯 과제 모두 실기 이전 (안정 실행·제어기 불안정 없음·과제 완료 기준). 단 이동 조작 과제는 VLA 파이프라인으로 시뮬에서만 검증 (p.13).
  • 모캡이 없어 실기는 정성 시연만, 정량 지표는 MuJoCo 로 대신 (p.13).
  • 주된 실패 원인: 구동기 모형·접촉 동역학의 sim2real 격차, 실제 구동기가 못 따라가는 과격한 동작. 무작위화와 정책 정규화로 해결 (p.13).
  • 동작 모방: 기본 BeyondMimic 설정은 시뮬 이전부터 실패 → 무작위화 + L2C2 추가 (p.10).
  • 배포: TorchScript + 자동 생성 YAML (관절 이름·관측 순서·이력 버퍼·행동 배율) 로 MuJoCo 와 실기가 같은 추론 코드를 쓴다 (p.8).

  • 에피소드 길이가 0 근처로 무너지면 "자살" 정책: 종료 벌점을 키우거나 가치 부트스트랩 종료 (σ 줄이기도 고려).
  • 보상은 과제 + 스타일 + 정규화 순서로, 처음엔 과제 + 기본 정규화만.
  • 시드 5 개 이상에서 확인. 시드 분산이 크면 보상·커리큘럼이 약하다는 뜻.
  • "가짜 부드러움": 시뮬 감쇠·마찰이 과격한 정책을 가린다 → 정책 출력 자체를 정규화 (행동 크기·변화율·가속, L2C2).
  • 실기가 시뮬과 크게 다르면 시뮬이 틀린 것: 보상으로 보정하지 말고 모형을 고칠 것.
  • 하체·상체를 함께 학습하지 않고, 보행을 먼저 학습 → 고정 → API 로 쓰며 상체 학습 (VIRAL 과 같은 접근, FAQ).
  • armature·PD 이득 범위 무작위화가 sim2sim 에 특히 중요 (FAQ).

10. 한계

  • 저자 언급 (p.13): G1·T1 두 로봇만, Isaac Lab API 의존, 과제가 주로 고유감각 기반 (지각 조작·달리기·계단 없음).
  • 이동 조작은 실기 검증 없이 시뮬 VLA 90 % 만. RL 전문가 성공률·실패 양상 없음.
  • 집어 놓기는 시연 궤적 추종으로 유도된 단일 물체 (0.2 kg) 과제이고, 하체 높이를 0.65–0.72 m 로 좁게 써서 쪼그림 이동 조작의 근거가 되지 못한다.
  • 하체 학습에서 걷는 중엔 상체 무작위가 없어, 걸으며 팔을 크게 쓰는 상황은 학습 밖일 수 있다 (코드 기준, 추론).
  • 논문 수치와 공개 설정이 다른 곳: 집어 놓기 에피소드 25 s 대 8 s, "오른팔·허리만" 대 하체 명령 4 포함.

11. 우리에게 가져올 것

  1. dev12 를 행동 항으로 감싸는 코드 꼴: AgileBasedLowerBodyAction 처럼 (a) TorchScript/ONNX 를 env device 에 올리고 (b) dev12 학습 때와 똑같은 관측 그룹을 별도 그룹으로 만들어 이력·배율까지 재현하고 (c) env 스텝마다 1 회 추론해 다리 12 목표를 내는 구조. 다만 dev12 는 상체 11 목표의 저역 통과 값과 변화율을 보므로, 그 필터 상태를 행동 항 안에 두고 상위의 상체 출력이 그 필터를 거쳐 PD 와 dev12 관측 양쪽에 같은 값으로 들어가게 해야 한다 (추론).
  2. 자르기만 하는 설계는 그대로 쓰지 않는다: AGILE 행동 항은 명령을 torch.clamp 만 하고 벌점이 없다 — v2 에서 std 발산을 부른 바로 그 꼴. 범위 밖 양에 L2 벌점 (VIRAL·DoorMan 식) 을 더하거나, 상체처럼 증분 누적 + 누적값 자체 자르기로 바꾼다.
  3. 상체 증분 누적 구현: 목표t = clamp(목표t−1 + a × 0.05, 한계), 자른 값을 다음 기준으로, 리셋 때 현재 관절로. 50 Hz 에서 a = 1 이 2.5 rad/s. K1 팔 (kp 22.3) 에도 바로 쓸 수 있는 크기. 허리는 roll·pitch ±0.1, yaw ±0.2 rad 로 따로 좁혔다 → K1 허리 yaw 도 처음엔 ±0.2 rad 로 (v2 의 허리 추종 실패 대책).
  4. 엔트로피 계수 자동 감쇠: 진행 10 % 이후 성공률 0.3 넘으면 반복마다 × 0.9998 (하체는 0.8 기준, 하한 0.001). std 발산 방지책으로 그대로 시도할 만하다.
  5. 가치 부트스트랩 종료 σ 5 + 보상 정규화 (β 0.999, ε 0.01): 박스 떨어뜨림·넘어짐을 −σ, 성공을 +σ, 시간 초과 0. 과제별 종료 벌점 손질이 줄어든다. 가치 손실이 오르면 σ 를 줄일 것.
  6. L2C2 (λπ 1.0, λV 0.1): 상위 출력의 고주파 떨림을 줄이는 값싼 정규화. 깊이 student 에도 적용 가능.
  7. 결정적 평가 시나리오: 고정 박스 위치·높이·질량 격자 시나리오를 Isaac 과 MuJoCo 에서 같은 코드로 돌리고 관절 한계 위반·저크를 함께 기록. "Isaac 에서 한계를 계속 어기면 sim2sim 실패" 라는 관찰은 v2 의 체크포인트 비단조 성공률 진단에도 쓸 수 있다.
  8. 하체 학습 쪽 점검 목록 (dev12 와 비교): AGILE 은 상체 무작위를 0.1–2.0 s 마다, 가속 1–10 rad/s², 최대 5–10 rad/s 사다리꼴로 줬고 걷는 중엔 끄고, 손목에 ±5 N 외력을 줬다. dev10 이 걸으며 박스를 들고 팔을 움직일 계획이라면 dev12 가 걷는 중 상체 변화를 봤는지 확인한다.

가져오지 말 것

  • 시연 궤적 추종형 상위 보상: 리타깃 시연이 필요하고, 받침대 높이·박스 자세가 바뀌는 우리 과제엔 기준 궤적이 하나로 정해지지 않는다. RSI 용 시작 상태 정도만 참고.
  • 하체 명령 범위를 좁게 잘라 쓰기 (높이 0.65–0.72 m): 우리는 0.335–0.77 m 와 pitch 가 핵심이다.
  • VLA 경로: 우리 student 는 깊이 + DAgger. 시연 100 개 + GR00T 미세조정은 목적이 다르다.
  • PhysX 전제 값 (마찰 결합 방식, 접촉 설정): 우리는 Newton 이고 마찰·외력 버그가 따로 있으므로 숫자를 그대로 옮기지 않는다.
  • 집어 놓기의 대칭 끄기: 한 손 과제라 끈 것. 우리 두 손 조이기는 좌우 거울 증강이 오히려 맞다 (박스 yaw ±40° 도 거울 변환 가능).
