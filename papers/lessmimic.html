1. 문제와 과제

  • 문제 (p.1): 참조 동작 기반 정책은 특정 물체 기하에 묶여 새 모양에서 실패하고, 실시간으로 참조에서 벗어나는 것을 "추종 실패"로 벌한다. 참조 없는 정책(PhysHSI 등)은 과제별 보상·관측이라 기술을 이어 붙이지 못한다.
  • 주장: 물체 표면까지의 거리장(Distance Field, DF)이 "기하에 무관하고 과제 공통인 상호작용 표현"이다. 손이 물체를 잡을 때의 국소 DF 구조는 물체 크기·접근 방향과 거의 무관하다 (p.1–2).
  • 과제 4 개 (p.6): PickUp = 바닥의 크기 다른 상자를 두 손으로 들어 안정적으로 잡고 있기. SitStand = 높이 다른 의자에 골반 접촉. Push = 손 접촉을 유지하며 밀기. Carry = 상자를 집어 정해진 경로로 나르기.
  • 실행 때 입력은 목표 루트 궤적 + 고유감각 + DF 잠재뿐. 참조 동작·과제별 보상·별도 계획기가 없다 (p.2).

2. 시스템 구조

표현

물체 자세(MoCap) 또는 1 인칭 깊이→ 링크별 ut = [Φ(x), ∇Φ(x), vnorm, vtan]→ 창 길이 l 이력 It→ VAE 인코더(MLP, ReLU) → 잠재 zt

학습 3 단계 (p.4–5, 그림 3)

πmimic = ResMimic (참조 동작 + 잔차, 고정 teacher)→ BC·DAgger 24,000 iter → πbase (Transformer, 입력 oprop·croot·z)→ AIP + AMP RL → πfull (물체 기하 무작위)→ DAgger 120,000 iter → πvis (깊이 인코더 Eφ + 같은 제어 머리)

실행

루트 궤적 명령 + 고유감각 + 깊이 이력 St→ πvis→ 전신 관절 행동→ 하위 전신 제어기 (논문에 설명 없음)

제어 주기, 하위 제어기 정체, 시뮬레이터는 논문에 없음. 세 단계 모두 같은 정책 구조를 쓰고 목적 함수만 바뀐다 (부록 A).

4. 보상 · 종료 · 커리큘럼

사전학습(BC)에는 보상이 없다. RL 후학습의 보상 rt = rtask + λi rinteract + λs rstyle (식 A4), 세부는 표 A2 (p.13).

6. teacher → student / 증류

이 논문의 핵심은 두 번의 teacher → student 단계다.

단계teacherstudent손실·방식정보 비대칭
① 상호작용 기술 사전학습πmimic = ResMimic(참조 추종 + 잔차), 고정πbaseLBC = Es∼πbase‖πbase(obase) − πmimic(omimic)‖² (식 3), DAgger: student 롤아웃 상태에서 teacher 라벨teacher 는 전신 참조 동작, student 는 루트 명령 + DF 잠재뿐
③ 시각 증류πfull (MoCap DF), 고정πvisLdistill = Es∼πvis‖πvis(ovis) − πfull(obase)‖² (식 8), DAgger, 강한 DRteacher 는 정확한 물체 자세로 만든 DF, student 는 깊이 이력에서 같은 기하 단서를 스스로 복원
  • ①과 ③ 사이에 RL 후학습(②)이 있다. BC 만 한 정책(절제 "− RL")은 PickUp 1.0× 31.7 %, 후학습 뒤 100 % (표 II) — teacher 를 흉내 낸 student 를 RL 로 다시 다듬는 것이 결정적이었다.
  • teacher 데이터의 물리 타당성: 원 MoCap 리타게팅 데이터를 그대로 쓰면(절제 "− Syn.") Carry 82.9 → 66.5 %, Push 51.3 → 41.9 %. ResMimic 으로 물리적으로 실현된 궤적을 만드는 이유.
  • 시각 증류 손실: PickUp 은 거의 그대로(1.0× 100 → 91.0 %, 1.4× 88.0 → 99.7 %), Carry 82.9 → 35.8 %, 5 과제 연결 61.7 → 15.9 %. SitStand 는 등 뒤 접촉이 1 인칭으로 안 보여 시각 판 평가 제외 (p.7).

10. 한계

  • 재현 정보 부족: 로봇·시뮬레이터·제어 주기·하위 제어기·행동 차원·DF 링크 목록·창 길이·망 크기·RL 알고리즘·DR 수치가 모두 논문에 없다.
  • teacher 가 ResMimic(참조 동작 필요)이라 새 과제마다 MoCap 참조와 그것을 추종하는 teacher 가 먼저 있어야 한다.
  • 본문 주장(80–100 %)과 표 II 수치가 어긋나는 셀이 있다. 시드 3 개.
  • 깊이 판은 단일 PickUp 외에는 크게 떨어진다(Carry 35.8 %, 5 과제 15.9 %). 등 뒤 접촉(SitStand)은 1 인칭으로 못 봄.
  • 저자: 관절·변형 물체로 확장, 부분 관측 강건성이 다음 과제 (p.8).

11. 우리에게 가져올 것

  1. 가져올 것 — 손별 DF 특징을 teacher 관측으로: 양 손바닥(공 손 중심)마다 [상자 표면까지 거리 Φ 1, 표면 법선 ∇Φ 3, 법선 속도 3, 접선 속도 3] = 10 차원. 상자 자세 그 자체보다 "어느 면에 얼마나 가까운가, 누르고 있나, 미끄러지나"를 직접 준다. 옆면 조이기에서 법선이 상자 좌우(±y) 면을 가리키는지가 바로 보이므로 한 손 밀기·앞면 대기를 정책이 구분하기 쉽다. 접선 속도는 들 때 상자가 손 사이로 미끄러지는지의 신호.
  2. 가져올 것 — student 보조 목표로 DF 특징: LessMimic 의 시각 증류는 깊이에서 DF 잠재를 복원하게 만드는 구조다. 우리 D436 student 에 "손바닥–상자 거리·법선 예측" 보조 헤드를 붙이면 dev10 v2 에서 student 격차의 원인으로 본 접촉 정보 부족을 부분적으로 메울 수 있다(깊이에서 기하로 계산 가능한 양이라 흉내 가능).
  3. 근거 — BC 만으로는 부족, student 를 RL 로 다듬기: BC 만 한 정책은 PickUp 31.7 %, RL 후학습 뒤 100 % (표 II "− RL"). 우리 DAgger student(Isaac 69 %, MuJoCo 50 %)도 DAgger 뒤 RL 미세조정 단계를 넣을 근거.
  4. 가져올 것 — 성공 정의: "상자 바닥이 지면 0.3 m 위, 3 s 이상 안정 유지"를 우리 받침대 높이에 맞춰 "시작 높이 + Δh, 3 s 유지 + 두 손 접촉 유지 + 넘어짐 없음"으로. 접촉률 지표(손 접촉 시간 비율, 몸통 위주 접촉은 실패)도 평가에 함께 기록한다 — 팔뚝·몸통으로 끌어안는 해를 거를 수 있다.
  5. 참고 — 크기 무작위는 고정 크기 과제에도: 기하 무작위를 빼면 학습 크기에서도 0 % (표 II "− Rand."). 우리 상자는 37×40.5×29 cm 하나지만 실물 오차·인지 오차를 감안해 각 축 ±10–20 % 정도의 크기 무작위를 teacher 에 넣는다(값은 우리 결정, 논문 수치 아님).
  6. 참고 — 시각 DR 목록: 카메라 자세 흔들림 + 에피소드별 외부 파라미터 무작위 + 깊이 양자화 + 결손 + 가산 잡음. 우리 D436 student 의 DR 항목 점검표로 쓴다(수치는 우리 실측 기준: 장착 오프셋, 프레임 나이).
  7. 참고 — 루트 궤적만 명령으로: 상위가 루트 궤적만 주고 손 동작은 상호작용 표현으로 알아서 하게 하는 구조는 우리 2 단계(접근·운반)에서 "골반 경로 명령 + 상체는 정책"과 같은 꼴이다.
  8. 가져오지 말 것 — AIP 판별기: 기준 상호작용 잠재 버퍼가 ResMimic teacher 의 성공 롤아웃에서 나온다. 우리는 참조 동작·teacher 데이터가 없어 판별기 기준을 만들 수 없다. 나중에 우리 teacher 성공 롤아웃으로 student 를 정규화하는 용도로나 고려.
  9. 가져오지 말 것 — ResMimic teacher 와 전신 행동: 우리는 하위(dev12)를 고정하고 상체 11 + 골반 명령만 낸다. 무릎 꿇고 집기(그림 5a)도 우리 하위 명령 공간(골반 높이 0.335 m 이상) 밖이다.
  10. 주의 — MLP 붕괴 결과: MLP 로 바꾸면 PickUp 0 % 였다. 이 결과는 여러 과제를 한 정책에 넣은 설정에서 나온 것이라 우리 단일 과제에 그대로 옮기긴 어렵지만, 상위 정책에 이력(행동·관측 몇 스텝)을 주는 근거로는 쓸 수 있다.
