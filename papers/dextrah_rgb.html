DextrAH-RGB: 스테레오 RGB 만으로 무엇이든 집는 손·팔 정책

DextrAH-RGB: Visuomotor Policies to Grasp Anything with Dexterous Hands

Ritvik Singh, Arthur Allshire, Ankur Handa, Nathan Ratliff, Karl Van Wyk · NVIDIA · UC Berkeley · arXiv 2412.01791 v2 (2025-02, 사전 공개) · Kuka LBR iiwa 7 + Allegro v4 (모터 23) · Isaac Lab (광선 추적 타일 렌더링)

로컬 PDF 로컬 코드 (DEXTRAH, dextrah_g 폴더) arXiv 2412.01791 NVlabs/DEXTRAH 프로젝트 페이지 유사도 3 NVIDIA License
DextrAH-G 와 같은 패브릭·행동 공간 위에서 teacher 를 ADR(성공률 게이트로 모든 무작위 범위를 함께 넓힘)로 학습하고, 스테레오 RGB 320×240 student(ResNet-18 + 교차 주의 transformer + LSTM)로 증류. KL 증류(σ 가중 L2)가 L2 보다 4 시드 모두 좋았다. 실기 빈 담기 SR 73–77 %, 주기 8.2–9.1 s: G 보다 1–2 s 빠르지만 10–14 %p 덜 믿을 만하다.

평가 배경: 보고서 의 "격차 대책 4. 분포 요령"에서 "KL 증류가 L2 보다 4 시드 모두 우수"로 인용, 유사도 3. 노트는 vision_teacher_student.md §1-11. 공개 코드는 DEXTRAH 저장소(로컬 reference/dextrah_g/code/)에 들어 있고, 그 설정이 이 논문과 가장 가깝다. 아래 내용은 논문과 그 코드에서 옮겼다.

1. 문제와 과제

  • 깊이 기반 집기는 투명·반사 물체, 직사광선에 약하고 깊이 잡음을 대규모로 흉내 내기 어렵다 (p.1–2).
  • 대부분 시뮬 시각 정책은 고품질 RGB 를 대량 렌더링 못 해 깊이로 제한된다 (p.1).
  • 목표: RGB 입력에서 곧바로 고속 행동을 내는 손·팔 집기, 시뮬만으로 학습해 실기 배포. 단안·스테레오 모두 지원 (p.2).
  • 기여: ① RGB FGP 를 시뮬만으로 학습 ② 스테레오 RGB 를 다룰 만큼 지각 구조 확대 ③ 실기 배포. 저자 주장으로 손·팔 접촉 과제에서 끝단 간 RGB 정책 sim2real 첫 사례 (p.2).

2. 시스템 구조

1 단계 · teacher (그림 2)

잡음 상태 관측→ teacher FGP: LSTM + MLP, 60 Hz (PPO 학습)→ 기하 패브릭 60 Hz (고정)→ PD 목표 → 시뮬 120 Hz
특권(완전) 상태→ critic: LSTM 2048 + MLP [1024, 512]→ PPO 손실

2 단계 · student (그림 3)

3 단계 · 실기 (그림 8b)

스테레오 RGB 60 Hz + 고유감각→ student 60 Hz (데스크톱 RTX 3090, CUDA graph)→ 상태 기계 60 Hz→ 패브릭 60 Hz (Jetson AGX Orin)→ PD 1 kHz / 333 Hz

그림 2·3 (p.3), 그림 7a (p.7), 그림 8 (p.8), p.5–6. 점선 = 그 단계에서 학습하지 않는 것.

패브릭(p.3): 기하 항이 속도와 무관한 경로를, 강제 항이 과제(목표 도달)를 맡는다. 원하는 행동은 가능한 한 기하에 넣는다(강제 항끼리 싸우면 행동이 무너짐). 충돌 회피는 주로 기하 항, 아주 가까울 때만 강제 항이 밀어냄. 팔꿈치 바깥·손가락 굽힘 자세 끌개, 관절 한계 강제 항, 가속·저크 한계, 근사 2차 RK 60 Hz 적분.

행동: 손바닥 6 자유도 + PCA 5 = 11 차원 목표를 패브릭에 줌 (p.3). [−1, 1] 출력을 범위로 사상: 손바닥 x −1.2–0, y −0.7–0.7, z 0–1 m, 방향 ±45°(README 실행값), PCA 는 상수 범위 (constants.py).

ADR 이 관측을 바꾼다(p.4, 표 IV): 정책에 들어가는 모든 속도·가속 입력에 계수를 곱해 1 → 0 으로 줄인다("observation annealing"). 정책이 추정값인 고차 신호 대신 직접 관측(위치)과 순환 기억에 기대게 하려는 장치.

종료

  • teacher: 최대 10 s (p.5). 코드는 물체가 작업 상자 밖(x −0.8 – −0.3, y −0.3 – 0.5 m) 또는 z < 0.2 m(탁자 아래)면 종료 (env.py L899–933).
  • student 증류: 물체를 공중에 2 s 들고 있으면 조기 종료 (p.6). 10 s 그대로면 에피소드 대부분이 "이미 든 상태"라 teacher 와 student 가 갈리는 잡기 구간이 묻힌다. 그래도 첫 시도 실패 뒤 다시 잡는 행동을 배우려면 충분히 길어야 한다 (p.5–6).

ADR (p.4, 그림 4, 표 IV)

  • 변수마다 초기값·끝값(또는 범위)을 정하고, 성공률이 충분하면 모든 변수를 함께 끝값 쪽으로 선형으로 한 칸씩 옮긴다(OpenAI 식 변수별 경계 탐색과 다름).
  • 코드: 50 칸, 게이트 = "성공 영역 안" env 비율 > 0.4, 직전 변경 뒤 리셋 호출 3,000 회(5 × 600, 에피소드 5 개 길이) 이상, 다중 GPU 는 가장 낮은 칸에 맞춤 (env_cfg.py L321–339, env.py L1117–1129).
  • student 는 끝값(최대 무작위)에서만 학습. teacher 는 끝값까지 도달한 것만 증류에 쓴다 (p.5–6).

G 와 다른 teacher 설정 넷 (p.4)

  1. PD 속도 목표 1 → 0: 초반에는 패브릭 속도를 PD 속도 목표로 넣어 응답을 빠르게(탐색에 유리), 끝에는 0 으로 G 와 같은 동역학.
  2. 관측 풀림 1 → 0: 속도·가속 입력을 지워 위치와 순환 기억만 쓰게.
  3. 패브릭 2 배 적분 + 감쇠 10 → 20: 시뮬 한 스텝에 패브릭을 두 번 적분해 빠르게 움직여 탐색하고, ADR 로 감쇠를 올려 실기 가능한 속도로 되돌린다.
  4. 외란 렌치 조건: G 는 들고 나서 켰지만, 여기서는 손이 물체 중심 0.3 m 안에 들어오면 켠다 → 쥐기 전에 물체가 움직여 더 반응적인 정책.

student 망 (p.5, 그림 7)

  • 왼·오른 영상 320×240 을 같은 사전학습 ResNet-18(마지막 두 층 제거)에 통과 → 영상당 40,960 차원 → MLP 로 16,384 → 128 차원 토큰 128 개.
  • 두 영상 토큰 + 학습 가능한 [embed] 토큰 → transformer 2 층. 교차 전용 마스크: [embed] 는 모두를 보고, 왼쪽 토큰은 [embed]·오른쪽 토큰만, 오른쪽은 [embed]·왼쪽만 본다(DUSt3R 식 암묵 스테레오 정합).
  • [embed] 출력 → MLP → 64 차원 스테레오 임베딩 ⊕ 고유감각 → LSTM 512 → (LSTM 출력 ⊕ 입력) → MLP [512, 512, 256] → 행동. 보조 머리 MLP [512, 256] → 물체 위치. 활성 ELU.

코드의 증류 루프 (distillation.py)

  • β 를 항상 0 으로: 환경은 student 가 표집한 행동으로만 진행(L365–380, L550–564). teacher 는 eval 모드, bf16 autocast.
  • 손실: weighted_l2(μs, μt, 가중 1/σt²) + l2(σs, σt) + aux_coeff × 보조 손실(L503–512). aux_coeff 기본 1, README 실행값 10. 보조 손실은 물체 위치 외에 영상 좌표·깊이 재구성 변형도 있음.
  • Adam 1e-4, grad clip 1.0, 매 스텝 갱신(순환 seq_length 를 1 로 덮어씀), env 가 끝나면 남은 손실도 반영, 100,000 반복, 5,000 마다 저장. 처음 5,000 반복은 백본 동결, 그 뒤 미세조정(L382–385).
  • 스테레오 인코더(stereo_encoder.py): ImageNet ResNet-18 의 avgpool 자리를 1×1 conv 512 → 128 + AdaptiveAvgPool (8, 16) 으로 바꿔 128 토큰 × 128 차원을 만든다(논문의 40,960 → 16,384 MLP 투영과 구현이 다름). transformer 2 층, 출력 MLP 128 → 64.

11. 우리에게 가져올 것

  1. 증류 손실을 σ 가중으로: L = Σi (μs,i − μt,i)² / σt,i² (+ 필요하면 σ 맞추기). 4 시드 모두 L2 보다 좋았다(p.5). 단, 우리 v2 처럼 teacher σ 가 일부 차원에서 커지면 그 차원 가중이 0 에 가까워져 student 가 무시한다 → teacher σ 상한을 두고, 가중 1/σ² 도 상한을 둔다(추론).
  2. 증류 에피소드 조기 종료: 상자를 들고 2 s 유지하면 끝낸다(p.6). 우리 student 격차가 접촉·잡기 구간에서 난다고 봤으므로, DAgger 데이터가 "이미 들고 서 있는" 상태로 채워지지 않게 한다. 실패 뒤 다시 잡기를 배울 만큼의 최대 길이는 유지.
  3. student 는 끝값 무작위에서만, teacher 는 끝값까지 간 것만 증류에 쓴다 (p.5–6).
  4. 성공률 게이트 ADR: 모든 무작위 범위를 50 칸으로 함께 넓히고, 성공 영역 비율 > 0.4 와 최소 간격(에피소드 5 개 길이)을 둘 다 만족할 때만 한 칸 (코드). 고정 무작위 대신 이 방식으로 시작하면 초반 탐색이 쉬워진다. 칸 수·게이트를 로그로 남겨 체크포인트 비교 때 같은 ADR 칸끼리 비교한다.
  5. 관절 PD 강성·감쇠 ×0.5–2 와 관측 잡음·편향(관절 위치 0.08 rad, 속도 0.18 rad/s, 편향 0.08)은 ADR 끝값 후보로 쓸 만하다. 단 팔 kp 22.3 에서 조임 힘은 kp 에 거의 비례하므로 ×0.5–2 는 조임 힘을 절반에서 두 배로 바꾼다(계산) → 팔 kp 범위는 실기 오차 실측으로 좁힌다.
  6. 여러 student 시드를 같은 teacher 로: 같은 teacher·같은 파이프라인이라도 시드마다 실기 결과가 다르다(p.8–9). 우리 Isaac 69 % → MuJoCo 50 % 같은 격차도 한 번의 숫자로 판단하지 말고, student 시드 3 개 이상을 MuJoCo 고정 평가셋으로 비교해 고른다.
  7. 보조 출력 + 상태 기계: 물체 위치 보조 머리 MLP [512, 256], 가중 1(논문)·10(README). 우리는 상자 위치(골반 좌표)·"들렸는가"를 함께 예측해 실기 단계 전환에 쓴다.
  8. 외란은 접근 단계부터: 손이 0.3 m 안에 들어오면 렌치를 켜 쥐기 전 물체가 움직이는 상황을 겪게 했다(p.4). 바닥 상자가 스스로 움직이진 않지만, 첫 접촉에서 상자가 밀려나는 상황(한 손 밀기 국소해)을 겪게 작은 수평 외란을 접촉 직전 구간에 주는 것은 고려할 만하다(추론). 크기는 아래 "가져오지 말 것" 참고.
  9. 배포는 평균 행동 + 자르기 + 고정 주기: 실기 노드는 μ 만 쓰고 [−1, 1] 로 자른다. 우리 student 노드도 결정적 순전파, 같은 자르기.

가져오지 말 것

  • RGB·스테레오·ResNet-18 + transformer student: 우리 입력은 D436 깊이 26×64 × 6 프레임. 53 시간 × L40S 4 장 규모의 시각 구조는 필요 없고, 시뮬 이득(단안 0.83 → 스테레오 0.89)도 실기에선 사라졌다.
  • 관측 풀림(속도 입력 지우기): K1 관절 속도는 엔코더로 직접 측정되고 dev12 도 속도를 쓴다. 지울 이유가 약하다(코드도 실제로는 처음부터 0 이라 논문 설명과 다름).
  • PD 속도 목표 1 → 0, 패브릭 2 배 적분: 하위층이 패브릭일 때의 탐색 요령. dev12 는 고정이라 해당 없음.
  • 외란 끝값 10 m/s²: 2 kg 상자면 20 N 으로 우리 손당 조임 어림 10–16 N(보고서 계산)보다 크다. 조임 마찰 여유 안에서만.
  • 논문 표 IV 숫자를 그대로: 코드와 여러 곳이 다르다(물체 위치 잡음 0.3 vs 0.03 등). 쓸 값은 코드에서 확인한 것만.
  • teacher 를 G 하이퍼파라미터로 "같다"고 가정: 실제 코드 값이 다르다. 우리 rsl_rl 설정은 우리 실험으로.
