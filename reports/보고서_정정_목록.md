# 보고서 정정 목록 (논문 상세 페이지 작성 중 원문·코드 대조로 찾은 것)

## 계층 IL 묶음 (demohlm hiwet refine_dp oil hugo r2s2)
- demohlm: 하위 동결이 그림 1(p.4)에 명시됨. LiftBox 등 4 과제는 순정 고무 손(그리퍼는 나머지 6 과제). "하위 분포 밖 명령"은 실패 원인으로 논문에 없음(sim2real 문제는 WBC 속도 추종 차이, p.10). teacher–student 없음. 실기 과제 수가 논문 안에서 6/7/10 으로 다름.
- hiwet: "12.4 mm, 한 팔"은 두 결과를 섞음 — 12.4 mm 는 하위가 두 손 명령을 따른 오차(표 1), 상위 실기 RMSE 는 12·15 mm(표 2). 높이 0.3–0.78 m 는 평가 명령 범위(학습 범위는 논문에 없음). 부록 없음.
- refine_dp: "+18 %"는 Task 2 한 과제 값(%p 인지 미상). 실기 20 회 Task 1 70 %·Task 2 50 %·Task 3 75 %. 과제는 받침 위 작은 물체 그리퍼 집기(상자 아님).
- oil: "행동 변화 L1 벌점"이 아니라 가중치 0.1 의 지수 커널 보상 exp(−s‖a_t − a_{t−1}‖₁), 대상은 MHC 20 관절 목표(p.6, 표 6). 학습은 MuJoCo(Isaac Gym 아님).
- hugo: PPO 384M 스텝은 기준선 설정, HuGo 자체는 LLM 이 짠 코드 정책(Lift Box 75.92 %). SONIC 24.91 % 실패 원인 = 손끝 오차 약 4 cm 로 상자를 밀어냄·접촉 유지 실패(p.6). 실기 66.7 % 는 기하 힌트 + SONIC 하위. RL 기준선은 시뮬만.
- r2s2: 43.29 %(w/o LS)를 "명시 명령 대 잠재" 근거로 쓰는 건 과함 — 여러 요소를 동시에 바꾼 기준선. 실기는 상자·목표 상태를 모션 캡처로 받음(p.8).

## 시각 SLIM 묶음 (slim nowyouseethat dexhumanoid_recipe)
- dexhumanoid_recipe(Lin et al., CoRL 2025): 권고 9 "접촉력·질량 critic 전용"의 근거로 약함 — 접촉력은 actor·critic 어디에도 없고, 질량은 critic 무작위화 배율로만.
- slim: DAgger·PPO 가 아님 — off-policy SAC + teacher KL(α 0.01, 고정 σ 0.05) + 혼합 rollout(β 0.5 → 1.0). teacher 성공률 표 없음(그림: teacher 약 0.95, student 약 85 %).
- "깊이만 0/10 vs 깊이 + 위치 10/10"은 들기·건네기만. 한 손 잡기는 깊이만 2/10.
- nowyouseethat 잡음 계수는 D436 에 그대로 쓰면 과함(1 m 에서 σ 약 2.4 cm vs D436 이론 약 5 mm).

## 운반 묶음 (hotice embrace boxlocomanip catchcarry)
- boxlocomanip(Xie): 손 목표는 "옆면 중심"이 아니라 "predefined points on the hands and on the box"(반대 옆면, p.8). r_box-hand 에 스케일 없음(0.1 m 오차도 약 0.98). 초록은 코드 제공이라 하나 PDF 에 링크 없음.
- hotice: "종료: 넘어짐·떨어뜨림·장애물 충돌"은 과제 실패 기준이고, RL 종료 조건은 논문에 없음.
- embrace: 학회 ICRA 2026(HOTICE 참고문헌 [27]). NSDF 절제는 관측과 보상을 같이 뺀 것.
- catchcarry: (−2, 2) 제한의 구현(자르기/눌러 담기)은 논문에 없음.

## 시각 VBC 묶음 (vbc prism ultra viloman visualmimic)
- vbc: "들렸는가" 보조 헤드는 논문에 없음 — 코드의 `--pred_success` 옵션(MLP student 만), 기본 GRU student·README 명령엔 없음 → 효과 미검증. 코드 기본 student = 3 프레임 54×96 GRU 128. 카메라 지연 코드 0.06–0.08 s. 정책 가중치 로컬 없음.
- prism: 발표처 CoRL 2026(PDF 1쪽 머리말; index 는 "프리프린트"). 공개 최종 student λ 0.01 → 0.9, 700 반복 간격(표 6 은 앞 단계 값). teacher 성공 129/137(94 %, 부록 C). "목 10° 어긋나면 OOD" 문턱은 논문에 없음. 지연 3–4 프레임은 코드 값.
- ultra: 97.57 / 67.30 / 85.03 % = teacher / 통합 student / 추종 전용 student(어블레이션) — 85.03 은 "미세조정 전"이 아님. 격차 원인은 여러 입력 방식을 한 모델에 묶은 비용(순수 DAgger 손실의 예 아님). 시뮬 점구름은 상자 표면에서 합성.
- viloman: teacher = 동결 GMT 에 참조 동작을 넣는 specialist 묶음. 84.91 → 77.55 % 는 test split.
- visualmimic: "Push Box 152 → 10"은 Distance 열(Forward 열은 151 → 8, 표 III). 마스크 25 % 는 마스크 한 개 크기. 하위 추종기는 .pt 안에 들어 있음(미공개 아님). μ±1.64σ 자르기의 실제 폭은 대부분 ±3–9 cm.

## DextrAH 묶음 (dextrah_g dextrah_rgb student_informed_teacher)
- dextrah_g: "접촉력 critic 전용 → student ≈ teacher 약 99 %"는 근거가 약함 — 99 % 는 성공 즉시 리셋되는 env 묶음 평균(쉬운 물체 쪽으로 기움), 물체별로는 student 80 % vs teacher 85 %(p.6–7, 부록 F.4). critic 전용 접촉이 격차를 줄였다는 절제 실험 없음(저자 "believe", p.5).
- dextrah_g: 질량은 actor·critic 어디에도 없음. 로컬 코드의 critic 접촉은 `hand_forces[:, :3]` 3 값(논문 손끝 12 값과 다름). LFS 포인터 447 = .usd 167 + .obj 280, 체크포인트 없음.
- dextrah_g 로컬 코드는 논문 G(15 Hz, Isaac Gym)가 아니라 DextrAH-RGB 시기 Isaac Lab 재구현(60 Hz, ADR). 깊이 증강 표의 값은 코드 값(논문은 막대 p 0.0025, 160×120).
- student_informed_teacher(SITT): 서랍 0.34 → 0.88 중 0.34 → 0.61 은 공유 디코더 + 특징 정렬 몫, KL 벌점·기울기 몫은 0.61 → 0.88(표 3). 본문 숫자와 표가 불일치.

## Hanoi 묶음 (humanoid_hanoi adaptmanip splitadapter hulk digitbox)
- splitadapter: 실기 16/27 → 26/27 은 어댑터 몫(같은 보상으로 학습, Base = 같은 고정 정책, p.5 §3.5·p.11). 약한 손 힘 보상은 두 행 모두에 있고 따로 시험 안 됨 → 그 보상의 근거로 쓰면 안 됨. 포화 "/20" 단위 없음("20 N"은 해석). 고무 손 아님 — "고마찰 장갑".
- hulk: 노트의 명령 범위(vx·vy ±0.5 등)는 비교용 시뮬 평가 범위(공통 팔 관절 8, p.6), 학습 범위는 논문에 없음. 몸통 roll·pitch 는 G1 허리 관절.
- adaptmanip: 식 2 에 "대칭 양손 접촉" 항 없음 — 접촉 항은 손 힘 합을 1 에서 자름(한 손만 닿아도 최대). 미끄럼 벌점은 인쇄된 대로면 부호 반대. λ 값 없음.
- digitbox(Dao): r_contact = ln(0.05·c_left + 0.05·c_right), t_contact 2 s 뒤만 — exp(−r) 틀에 넣으면 부호가 이상(오기 추정). "ICRA 2024"는 PDF 에 없고 남의 참고문헌에만.
- humanoid_hanoi: 공개본엔 학습·보상 구현 없음(`compute_rewards` 빈 dict, 장면·로그만). XML 은 cone elliptic·impratio 20. 코드 무작위화에 표 5 에 없는 항목(엔코더 오프셋 ±0.05 rad, 토크 지연 4–7 주기 @2 kHz, 토크 효율 0.9–1.0, 바닥 기울기 ±0.05 rad, 토크–속도 한계). Digit "손"은 아래팔 원통 — 아래팔로 상자를 끼움.

## CLoSD 묶음 (closd puppeteer hilmares whatmatters)
- closd: 노트 "원래 PHC 추적 보상·리셋 그대로"는 논문과는 맞지만 코드는 0.25 m 추종 이탈 리셋을 안 씀(넘어짐 리셋만). 일어서기 목표 논문 0.3 m vs 코드 1.0 m, DiP 체크포인트 200K vs 300K.
- puppeteer: "51명 중 97.8 %"는 응답 510 개(51명 × 10쌍) 중 97.8 %. 상위 출력은 "실측 끝점 + 0.3·a" 델타 명령. 상위 MPPI 반복 코드 6회(표 5 는 8).
- hilmares: "상위 명령을 하위 학습 범위로 자름"은 논문에 없음(추론).
- whatmatters: "환경 안 자르기 → std 발산"을 직접 뒷받침하지 않음 — 논문 기본 설정이 환경 clip·벌점 없음·엔트로피 0 이고 clip 은 tanh 보다 약간 나쁠 뿐. v2 의 발산은 clip + 엔트로피 0.005 겹침으로 추정. 로컬 PDF 는 arXiv v1(2020-06).
- (정정) whatmatters 페이지가 "v2 teacher 관측 정규화 끔"이라 쓴 근거 파일은 9월 역할 분리 판(k1_boxlift) 설정 → 페이지 문장 고침. v2(sonic_pick, TRL ppo_im_phc)는 미확인.

## ASE 묶음 (ase pulse omnigrasp maskedmimic)
- pulse: "고정 σ 0.22"는 논문상 "fixed variance (0.22)"(σ 약 0.47), 공개 설정은 log σ −1(σ 약 0.37). "하위 과제에서 처음부터 학습보다 낫다"는 생성 과제만 — VR 추적은 처음부터 쪽이 위치 오차가 작음(51.7 vs 57.8 mm 등).
- omnigrasp: PULSE-X 제거·PPO-10B 에서 크게 떨어지는 건 궤적 성공률뿐, 잡기 성공률은 거의 그대로(표 4: R1 잡기 97.0 %·궤적 33.6 %, PPO-10B 98.4 %·55.9 %). 30 mm 오차 원인에 MoCap–시뮬 체형 차이도.
- ase: "처음부터 학습이 return 더 높다"는 5 과제 중 4 과제(Reach 는 ASE 0.75 > 0.56). "고정 판별기 악용"은 논문이 ASE 에선 대부분 사라졌다고 반박.
- maskedmimic: 로컬 ProtoMotions 3 에는 CALM·PULSE 구현 없음. Apache-2.0 은 코드만, 가중치는 NVIDIA Open Model License. PULSE 비교 수치는 PULSE 논문 보고값 그대로.
- 보고서 상위 주기 권고(ASE 6 Hz)의 반대 근거: PULSE 표 2 에서 같은 ASE 잠재를 30 Hz 로 쓰면 6 Hz 보다 나음(시험 성공 37.6 vs 33.3 %).

## PhysHSI 묶음 (physhsi hdmi omnicontact lessmimic resmimic)
- physhsi: Carry Box 성공률 논문 안 불일치(표 I 91.34·84.60, 본문 81.34, 표 II 79.34). 상자 폭 코드 격자 0.21–0.39 m(0.2–0.5 는 본문). 상자 마찰·반발 DR 은 코드에서 꺼짐(`random_props = False`). actor 이력 코드 6(논문 5). 스타일 보상 코드 = LSGAN × 0.5.
- hdmi: 접촉 상실 종료 코드 = "거리 ≥ 0.2 m 또는 힘 < 1 N" 25 스텝 연속. 물체 자세 종료 코드 0.8 rad(논문 1.2). 공개 코드에는 ROA 식 teacher→student 경로 있음(논문엔 없음).
- omnicontact: 추종:AMP 코드 0.9:0.1(논문 0.85:0.15).
- lessmimic: "추종 보상 뺐다"와 달리 부록 표 A2 에 루트·물체 궤적 추종 보상(각 1.0). 초록 "0.4–1.6× 80–100 %"가 표 II 와 불일치(PickUp 0.4× 63.0 등).
- resmimic: 핵심 장치 셋(가상 물체 PD 힘 커리큘럼, 접촉 보상, 접촉 10 프레임 상실 종료)은 공개 코드에 없음 — 코드는 물체 점구름 오차 > 0.3 m 종료. 물체 관측은 현재 위치·자세 7 차원뿐. 코드에 TWIST2 식 DaggerPPO 경로가 있어 base_policy.pt 학습 방식은 불명.

## VIRAL 묶음 (viral doorman agile homie amo)
- viral: "명령 자르기 + 잘린 양 제곱 벌점"은 VIRAL main 설정에서 안 씀(함수만 있음). 실제는 자르기 전 명령의 경첩 벌점 max(0, |cmd| − 문턱) × (−20), 문턱 코드 vx·vy 0.4·ωz 0.8(표 3 은 0.5). 잘린 양 제곱 벌점(−1.0)을 쓰는 건 DoorMan. VIRAL teacher 가 움직이는 건 속도 3 + 오른팔 7 + 오른손 1(증분 11), 높이 0.74·rpy·왼팔 고정. 카메라 지연 "2–3 스텝" 근거 없음(코드 고정 1 또는 무작위 1–5). 공개 teacher 설정에 물리 무작위화 없음.
- doorman: student 정체 원인을 논문은 시야 가림(부분 관측)으로 설명 — "접촉 렌치 탓"은 보고서 추론. 증분 배율 0.3·19 개(양팔), ωz ±0.5. 스냅숏 버퍼 코드 200(논문 100). teacher 손 접촉 코드 48(손당 8 몸체 × 힘 3).
- agile: RL 집어 놓기 정책은 상체뿐 아니라 하체 명령 4 도 냄(vx −0.2–0.5, vy ±0.4, ωz ±0.5, 높이 0.65–0.72 로 자름). `AgileBasedLowerBodyAction` 은 벌점 없이 `torch.clamp` 만 → 그대로 쓰면 v2 std 발산 꼴, 벌점 추가 필요. "시뮬 90 %"는 GR00T N1.5 VLA 성공률(RL 전문가 성공률은 논문에 없음). 공개 코드는 PhysX(Newton 흔적 없음).
- homie: 쪼그림 0.24–0.74 m(논문 표 "−0.24"는 오기). 하체는 속도 0 일 때만 쪼그림 — 쪼그린 채 걷기는 학습에 없음. 마찰 코드 0.1–3.0.
- amo: RSS 2025 확인. 하체 student 는 "지도 학습"(DAgger 언급 없음). 회전 명령은 목표 heading.
